# 🧧 运气王预言家 · Luck King Odds

> 微信群里发了个拼手气红包？丢一张「红包详情页」截图进来，本工具会自动识别已抢金额，**反推红包总额**，并算出**你成为运气王的概率**。

纯前端 · 零依赖框架 · 识别与计算全部在**你的设备本地**完成，图片和数据**不会上传到任何服务器**。

**在线使用**：https://1450461534.github.io/luck-king-odds/ （手机 / PC 浏览器均可）

---

## 它能做什么

- 📷 **零输入**：上传 / 拖拽 / Ctrl+V 粘贴一张红包详情页截图，自动识别领取记录
- 💰 **反推总额**：已抢金额是总额的「信息泄漏」——抢的人越多、金额越大，总额被卡得越准
- 📊 **运气王概率**：基于二倍均值法做蒙特卡洛模拟，给出你（下一个抢 / 已抢）最终成为运气王的概率，以及每个位置的概率分布
- 🏆 **抢完判定**：红包抢完后传最终截图，直接告诉你运气王是谁、你是不是
- 📈 **预测 VS 实际**：预测自动存档，抢完后传最终截图即可自动验证，累计看「平均预测 vs 实际命中」

## 使用方法

1. 微信群里点开红包详情页（显示领取列表的那个页面），**截图**
2. 打开本页面，把截图丢进上传框
3. 识别结果里点一下「我」标记自己（还没抢就不选）；补一下「红包总个数」（详情页顶部红底区域文字暂无法识别）
4. 点「🔮 计算」看结果
5. 等红包抢完后，再把最终详情页截图传一次 → 历史记录自动验证你的预测

> 也可以先点首页的「试试示例」感受一下。

## 原理（为什么可行）

微信拼手气红包采用社区共识的**二倍均值法**：金额在**拆红包瞬间实时随机生成**，不是发红包时预分配的。因此：

1. **没被抢的份额金额尚不存在**，只受「剩余金额 + 二倍均值」约束——第 i 个抢的人满足 `xᵢ ≤ 2(M − Sᵢ₋₁)/(n − i + 1)`，反解后每个观测都给总额 M 一个硬下界；
2. 现实中总额几乎总是**整数元**（1 / 5 / 10 / 66 / 88 / 100…），候选总额在这些整数里枚举，用似然加权归一；
3. 对每个候选总额按二倍均值法**蒙特卡洛模拟**剩余所有人的抽取（含末位 take-all、每人至少 0.01 元保底、金额并列时先抢者得运气王），统计每个位置成为运气王的频率，再按总额后验加权。

### 关键结论（实测）

- 抢到的金额期望与顺序无关，但**方差随顺序增大**：越后抢越容易爆运气王，也越容易垫底
- 已观测的大额会「压住」排它前面的位置（它们永远当不了运气王）
- 只抢了 1~2 人时总额估计很长尾；3~5 人后明显收敛

更详细的推导见 `luck.js` 源码注释和 `test.mjs` 中的断言。

## 本地运行

无需安装任何依赖，直接用浏览器打开 `index.html` 即可（识别引擎已随仓库自托管，离线可用）。

或起一个本地静态服务：

```bash
python -m http.server 8080
# 打开 http://localhost:8080
```

命令行体验 / 测试：

```bash
node demo.mjs   # 示例：反推总额 + 运气王概率
node test.mjs   # 算法与解析器自校验
```

## 项目结构

```
index.html   网页 UI（零框架，原生 JS）
app.js       交互状态机 + 预测 VS 实际历史（localStorage）
luck.js      核心算法：总额反解、似然、蒙特卡洛（浏览器 / Node 双端）
ocr.js       截图 OCR 封装 + 结构化解析器（Tesseract.js，本地自托管）
tesseract/   识别引擎与中文模型（Apache-2.0，自托管保证离线可用）
test.mjs     算法与解析器测试（含真实截图样例）
demo.mjs     命令行示例
```
