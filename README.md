## 它能做什么

一个 10 人的红包只有 3~5 个人抢了。你盯着详情页里那几个金额心里嘀咕：

1. **这红包总共多少钱？** —— 已抢金额是总额的「信息泄漏」：抢的人越多、金额越极端，总额被卡得越准
2. **我现在抢，能当运气王吗？** —— 基于二倍均值法做蒙特卡洛模拟，给出概率
3. **红包抢完了，谁是运气王？** —— 直接判定
4. **我的预测准不准？** —— 预测自动存档，抢完后再传一次最终截图即可自动验证，累计查看「平均预测 vs 实际命中」

## 网页版使用方法

1. 在微信里打开红包详情页（有领取金额列表的那个页面），**截图**
2. 打开 [网页版](https://1450461534.github.io/luck-king-odds/)，把截图拖进去（支持 **一次多张**、Ctrl+V 粘贴、点击选择）
3. 等待识别（首次使用浏览器会下载识别模型，之后有缓存）
4. 在确认页核对识别出的金额（可点改 / 插行 / 删行），点一下「我」标记自己，补一个「红包总个数」
5. 点「🔮 计算」出结果

> 没有截图？首页有「试试示例」按钮，可以先感受完整流程。

## Android APK 使用方法

### 安装

1. 到 [Releases](https://github.com/1450461534/luck-king-odds/releases) 下载最新的 `luck-king-odds-debug.apk`
2. 手机安装（需允许「安装未知应用」）
3. 打开应用 → 点「开启读屏（跳转系统设置）」→ 在无障碍列表里开启「运气王预言家」
   - **荣耀 / 华为 / Android 13+**：如果无障碍开关是灰色的，先去 设置 → 应用 → 运气王预言家 → 右上角 ⋮ → **「允许受限设置」**（需指纹确认），再回来开启

### 日常使用

1. 微信红包详情页**截图**（电源键 + 音量下键）
2. 打开本应用 → 会**自动检测最新截图**并离线识别 → 金额列表自动填入确认页
3. 补一个「红包总个数」→ 点「🔮 计算」

| 权限 | 用途 |

| 无障碍服务（可选） | 读取当前屏幕的窗口列表状态，用于显示「荣耀已隔离微信窗口」的诊断信息 |

## 原理：为什么可以预测

微信拼手气红包采用社区共识的**二倍均值法**：金额在**拆红包瞬间实时随机生成**，不是发红包时预分配的。因此：

1. **没被抢的份额金额尚不存在**，只受「剩余金额 + 二倍均值」约束——
   第 i 个抢的人满足 `xᵢ ≤ 2(M − Sᵢ₋₁)/(n − i + 1)`，反解后每个观测都给总额 M 一个硬下界；
2. 现实中总额几乎总是**整数元**（1 / 5 / 10 / 66 / 88 / 100…），候选总额在这些整数里枚举，用似然加权归一；
3. 对每个候选总额按二倍均值法**蒙特卡洛模拟**剩余所有人的抽取
   （含末位 take-all、每人至少 0.01 元保底、金额并列时先抢者得运气王），
   统计每个位置成为运气王的频率，再按总额后验加权。

### 实测结论

- 抢到金额的期望与顺序无关，但**方差随顺序增大**：越后抢越容易爆运气王，也越容易垫底
- 已观测的大额会「压住」排它前面的位置（它们永远当不了运气王）
- 只抢了 1~2 人时总额估计很长尾；3~5 人后明显收敛

详细的算法实现见 `luck.js` 源码注释；`test.mjs` 中有用真实红包截图验证过的测试样例。

## 已知限制（重要，请先读）

### 1. 荣耀 / 华为系 ROM 无法实时读屏（APK 的悬浮窗方案受限）

本项目最初尝试「无障碍服务实时读取微信窗口」，但在荣耀 300U（MagicOS）实测：
**系统将微信窗口内容对第三方无障碍服务整体隔离**（`rootInActiveWindow` 可访问但节点树为空，
遍历系统所有窗口也只能拿到空壳）。这是 ROM 级限制，第三方应用无法绕过
（同类自动记账应用在华为/荣耀上的已知问题同源）。

因此 v1.1.0 起识别主通道改为**截图 OCR**：
无障碍服务保留用于状态诊断（服务是否开启、是否收到微信事件），不再承担内容识别。

### 2. 红包总个数需要手动补一个数字

详情页顶部的「N个红包」文字位于红底横幅区域，OCR 识别率低。
请在确认页手动填写总个数（就一个数字）。

### 3. OCR 识别率依赖截图质量

实测微信详情页（放大 2x + 灰度化预处理后）金额识别率很高，
但请确保截图包含完整的金额列表、截图清晰。识别结果在确认页**逐行可核对修改**。

### 4. APK 为 debug 签名（v1.1.0 起为固定自签证书）

签名证书随仓库分发（`android/keystore/lko.p12`，纯本地玩具应用，仅用于保证升级连续性）。
**不要**把它当安全凭证使用。

## 本地运行与构建

### 网页版（零依赖）

```bash
# 直接用浏览器打开 index.html 即可，或者：
python -m http.server 8080
# 打开 http://localhost:8080
```

### 网页版测试

```bash
node test.mjs   # 算法与解析器自校验（含真实截图样例）

```

### Android APK 构建

```bash
cd android
gradle assembleDebug
# 产物：android/app/build/outputs/apk/debug/app-debug.apk
```

需要 JDK 17 + Android SDK（compileSdk 34）。CI 用户无需手动构建——
push tag 后 GitHub Actions 自动构建并挂到 Releases（见 `.github/workflows/build-apk.yml`）。

## 常见问题 FAQ

**Q：悬浮窗怎么不弹？**
A：荣耀 / 华为系 ROM 会隔离第三方无障碍对微信窗口内容的读取（本项目实测确认），
实时读屏路线在这类设备上不可行。请使用截图方式：微信里截图 → 打开应用自动识别。

**Q：网页版 OCR 首次很慢？**
A：浏览器首次会下载中文识别模型（约 20MB），之后有缓存。识别完全在本地浏览器完成。

**Q：总额估不准？**
A：已抢人数太少时（1~2 人）后验很宽是正常现象；3~5 人后明显收敛。
另外总额非整数元时模型会有偏差（现实中几乎总是整数）。

**Q：APK 为什么有 47MB？**
A：内置了 ML Kit 中文 OCR 模型（约 20MB）+ Tesseract 引擎与模型（约 40MB，供网页识别），
换取完全离线、无需联网的体验。

**Q：会封微信号吗？**
A：本工具是「人工截图 + 本地计算」，不触碰微信进程、不模拟点击、不发协议请求，
与外挂完全无关。正常使用没有封号风险。
